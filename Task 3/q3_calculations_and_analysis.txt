================================================================================
Q3 - WHY DOES THE HOME PAGE TAKE 8 SECONDS? (CALCULATIONS & ANALYSIS)
================================================================================

1. WORK OUT (RTT = 50 ms, 1 Base HTML + 80 Embedded Objects = 81 Total Files)
--------------------------------------------------------------------------------
(a) Non-Persistent HTTP (1 TCP connection at a time):
    - Each file requires 1 RTT for the TCP 3-way handshake + 1 RTT for HTTP
      request/response = 2 RTT per object.
    - Total Time = 81 files * 2 RTT = 162 RTT
    - In milliseconds = 162 * 50 ms = 8,100 ms (8.10 seconds)

(b) Persistent HTTP/1.1 (Single reused TCP connection):
    - Without Pipelining:
      * 1 RTT (initial TCP handshake) + 81 * 1 RTT (sequential object fetches)
      * Total Time = 82 RTT = 82 * 50 ms = 4,100 ms (4.10 seconds)
    - With Pipelining:
      * 1 RTT (handshake) + 1 RTT (HTML) + 1 RTT (all 80 requests pipelined)
      * Total Time = 3 RTT = 3 * 50 ms = 150 ms (0.15 seconds)

(c) 6 Parallel Non-Persistent Connections:
    - Base HTML file = 2 RTT.
    - Remaining 80 objects across 6 parallel connections = ceil(80 / 6) = 14 rounds.
    - Each round of non-persistent fetches takes 2 RTT -> 14 * 2 RTT = 28 RTT.
    - Total Time = (2 + 28) RTT = 30 RTT = 30 * 50 ms = 1,500 ms (1.50 seconds)

(d) HTTP/2 vs. HTTP/3 Head-of-Line (HoL) Blocking:
    - HTTP/2: Multiplexes multiple logical streams over a SINGLE TCP connection.
      If one TCP segment is lost, the OS kernel holds all subsequent segments in
      the TCP receive buffer until retransmission arrives, stalling all streams.
    - HTTP/3 (over QUIC/UDP): Runs independent streams in user space; a lost
      packet in Stream A pauses only Stream A while Streams B and C continue.

(e) Caching Headers on Repeat Visits:
    - Cache-Control: max-age=86400, immutable
      Eliminates all network round trips for static assets (0 ms network delay;
      page loads from local disk/memory cache in < 50 ms, saving ~8.05 s).
    - ETag / If-None-Match:
      Sends a conditional request (1 RTT for HTTP 304 Not Modified), avoiding
      re-downloading unchanged file payloads.

2. ENGINEERING DECISION (RANKED CHANGES FOR MOBILE NETWORKS)
--------------------------------------------------------------------------------
1. Strong Cache-Control Headers: Cuts repeat-visit load time by ~99% to 0 RTT.
2. Upgrade to HTTP/3 (QUIC): Reduces handshake RTTs and eliminates TCP HoL
   blocking on lossy 4G/5G cellular networks.
3. Asset Bundling & Compression: Reduces total HTTP object count and payload size.

3. ALTERNATIVE CONCEPT ANALYSIS (BUNDLING 80 OBJECTS INTO 8 BUNDLES = 9 FILES)
--------------------------------------------------------------------------------
- Total files reduced from 81 (1 HTML + 80 objects) to 9 (1 HTML + 8 bundles).
- Non-Persistent HTTP (sequential):
  9 files * 2 RTT = 18 RTT = 18 * 50 ms = 900 ms (down from 8,100 ms; 88.9% faster).
- Persistent HTTP/1.1 (without pipelining):
  1 RTT + 9 RTT = 10 RTT = 10 * 50 ms = 500 ms (down from 4,100 ms; 87.8% faster).
- Comparison with HTTP/2 Multiplexing:
  HTTP/2 achieves ~150-200 ms over a single connection WITHOUT bundling, and
  avoids cache invalidation penalties (under bundling, changing 1 line of CSS
  forces clients to re-download the entire bundle).
